# QPL Fantasy — фэнтези-футбол по Казахстанской Премьер-лиге

Спецификация (дизайн-документ) · 22 октября 2026
Статус: на согласовании

Название игры: **QPL Fantasy**.

---

## 1. Цель

Фэнтези-игра по образцу Fantasy Premier League, но для **Казахстанской Премьер-лиги (ҚПЛ)**. Игрок собирает виртуальную команду из реальных футболистов ҚПЛ и получает очки за их действия в настоящих матчах.

**Этапы:**
1. **Сообщество (сезон 2027):** бесплатная игра для друзей и футбольных чатов, проверка идеи.
2. **Бизнес (позже):** рост аудитории, доход от рекламы и спонсоров, партнёрство с ПФЛК/ҚФФ. Архитектура с самого начала строится так, чтобы этот переход не требовал переписывания.

**Критерии успеха первого сезона:**
- игра работает все 30 туров ҚПЛ-2027 без ручного «латания» каждый тур;
- очки считаются верно и обновляются во время матчей с задержкой до ~5 минут;
- игроки сами зовут друзей через мини-лиги в Telegram.

**Команда:** код пишет Claude, владелец проекта (не программист) участвует в решениях и понимает каждый шаг.

### 3.1 Стиль «C 3.1»

- **Характер:** светлый, мягкий, «выпуклый» (3D): у кнопок, плашек и карточек есть нижний «бортик» (тень снизу на 2–4 px).
- **Шрифты:** Rubik (цифры, заголовки) и Nunito (текст). Оба поддерживают казахские буквы.
- **Фирменный знак:** **шаңырақ**. Он есть в логотипе (раздел 3.2), в центральном круге поля и в водяных знаках карточек.
- **Поле** показано с лёгкой перспективой: нападающие «дальше» и чуть меньше.
- **Футболки:** объёмные (блик, тень, складки), цвета формы клуба. Логотип клуба маленький, на левой стороне груди. Под футболкой подпись: фамилия, код клуба (ҚАЙ, АҚТ…), очки и **цветная полоска клуба** из двух его цветов. Так различаются клубы с похожей формой (Ақтөбе и Қайсар, Тобыл и Елімай).

## 4. Правила игры

### 4.1 Состав
- Бюджет **100 млн**, стартовая цена игрока **4.0–10.0 млн** (за сезон может меняться в пределах 3.5–12.0).
- **15 игроков:** 2 вратаря, 5 защитников, 5 полузащитников, 3 нападающих.
- **Не больше 3 игроков из одного клуба.**
- В основе 11, в запасе 4 (порядок запасных задаёт игрок).
- Схема любая при условии: **1 вратарь, ≥3 защитника, ≥1 нападающий**.

### 4.2 Тур и дедлайн
- 16 клубов, **30 туров**, март – ноябрь (если формат лиги не изменится).
- **Дедлайн:** за 1 час до первого матча тура, по серверному времени.
- После дедлайна состав на тур «замораживается».
- **Перенесённый матч** засчитывается в тот тур, в котором его реально сыграли. Если у команды два матча в одном туре («двойной тур»), её игроки получают очки за оба.

### 4.3 Трансферы
- До дедлайна 1-го тура трансферы **без ограничений**. Новичок, пришедший посреди сезона, тоже собирает первый состав бесплатно.
- **1 бесплатный трансфер за тур**, неиспользованные копятся (максимум 5).
- Каждый лишний трансфер стоит **−4 очка**.
- **Wildcard:** неограниченные бесплатные трансферы на один тур. Даётся 2 раза за сезон: один на туры 1–15 и один на туры 16–30.
- Трансферы на следующий тур открываются **сразу после дедлайна** текущего.
- Продажа игрока идёт **по текущей цене**.
- **Цены меняются один раз между турами** по чистым покупкам (покупки минус продажи) относительно числа всех участников: ≥5% → +0.1, ≥10% → +0.2, ≥20% → +0.3; так же вниз при чистых продажах. Пороги хранятся в настройках сезона.

### 4.4 Очки

| Действие | Очки |
|---|---|
| Сыграл 1–59 минут / 60+ минут | 1 / 2 |
| Гол: вратарь или защитник / полузащитник / нападающий | 6 / 5 / 4 |
| Ассист | 3 |
| «Сухой» матч (60+ минут на поле): вратарь или защитник / полузащитник | 4 / 1 |
| Отбитый пенальти / незабитый пенальти (если событие есть в данных) | +5 / −2 |
| Каждые 2 пропущенных мяча (вратарь, защитник) | −1 |
| Жёлтая / красная карточка / автогол | −1 / −3 / −2 |

Уточнения:
- «Сухой» матч и пропущенные голы считаются **только за время, пока игрок на поле**.
- **Капитан** получает очки ×2. Если капитан не сыграл, ×2 получает вице-капитан. Если не сыграли оба, удвоения нет.
- **Автозамена:** игрока основы, не вышедшего на поле, заменяет первый по порядку запасной, если схема остаётся допустимой. Вратаря меняет только вратарь.
- **Равенство в лиге:** выше тот, у кого меньше платных трансферов за сезон.
- Таблица очков хранится в базе как **настройка сезона**: её можно поменять без переписывания кода.
- **Минуты** считаются из состава, замен и удалений: стартовый игрок — с 0-й минуты до замены, удаления или конца матча; запасной — с минуты выхода.
- **Сейвов и рейтинга в данных нет**, поэтому очков за сейвы и бонуса за рейтинг в сезоне 2027 нет. Если лига даст доступ к своей статистике, их можно вернуть настройкой сезона (строки в таблице правил), без переписывания кода.
- Любой показатель можно поправить вручную в админке (`manual_override`).

### 5.1 Mini App (фронтенд)
- React + TypeScript + Vite, хостинг Cloudflare Pages (бесплатно).
- Telegram Mini App SDK: данные пользователя, тема, кнопка «назад», вибрация.
- Языки kk/ru (файлы переводов, переключатель в профиле).
- Отдельные переиспользуемые компоненты: `Kit` (SVG-футболка с логотипом), `PlayerToken`, `Pitch`, `Chip3D`, `BottomNav`, `Sheet`.
- Приложение только **показывает** данные и **отправляет** намерения («хочу трансфер X → Y»). Решения принимает сервер.

### 5.2 Серверные функции (Supabase Edge Functions)

| Функция | Что делает |
|---|---|
| `auth-telegram` | проверяет подпись Telegram `initData` и выдаёт сессию |
| `squad-save` | сохраняет основу, порядок запасных, капитана и вице (до дедлайна) |
| `transfer-commit` | выполняет трансфер(ы) атомарно: проверка бюджета, 3 на клуб, состава, дедлайна, штрафа, Wildcard |
| `league-create` / `league-join` | создаёт мини-лигу и вступает в неё по коду |
| `admin-*` | правка статистики, цен, клубов, форм и логотипов; каждое действие пишется в журнал |
| `bot-webhook` | принимает сообщения боту: `/start`, ссылки-приглашения в лигу |

### 5.3 Задачи по расписанию (pg_cron → функции)

| Задача | Частота |
|---|---|
| `sync-fixtures`: календарь, переносы | каждые 3 часа |
| `sync-live`: события идущих матчей (голы, ассисты, карточки, замены) | страница каждого идущего матча раз в 2–3 минуты (5.4) |
| `sync-final`: итоговые составы и события, расчёт минут | после финального свистка и повторно через 2 часа (лига может поправить протокол) |
| `score`: пересчёт очков футболистов, команд и таблиц | после каждого обновления данных |
| `gameweek-finalize`: автозамены, финальные очки и места, рассылка итогов | после последнего матча тура; окончательно через 24 часа |
| `prices-update`: новые цены | между турами |
| `notify`: напоминания о дедлайне | за 24 часа и за 2 часа |
| `backup`: копия базы | раз в неделю |

### 5.4 Загрузка данных с kffleague.kz
- Данные берём со **страниц** сайта (`/ru/matches/<id>`, `/ru/player/<id>`): они встроены в HTML. Внутренний `/api/` сайта закрыт в `robots.txt`, его **не используем**.
- Нужны: составы с позициями, голы с ассистентами, пенальти, карточки, замены, счёт и статус матча.
- **Бережная нагрузка:** не чаще 1 запроса в 2–3 минуты на идущий матч (в игровой день до ~5 матчей одновременно), календарь — раз в 3 часа. Все запросы пишутся в `source_usage`.
- Загрузчик изолирован в одном модуле («адаптер источника»): при переходе на официальный доступ от лиги меняется только он.
- **Цель для этапа 2:** договориться с лигой об официальном доступе к данным (включая сейвы и статистику матча).

### 5.5 Telegram-бот
- `/start` → кнопка «Ойнау» открывает Mini App.
- Приглашение в лигу: ссылка вида `t.me/<бот>?startapp=league_<КОД>` сразу открывает лигу.
- Уведомления: дедлайн, итоги тура, «тебя обогнали в лиге». Уведомления можно отключить в профиле.

## 7. Жизненный цикл тура

1. **Открыт:** трансферы и изменения состава, все проверки на сервере.
2. **Дедлайн:** снимок составов на тур.
3. **Идут матчи:** live-обновления → статистика → очки → таблицы лиг.
4. **Финальный свисток:** итоговая статистика и бонус.
5. **Сыгран** (последний матч завершён): автозамены, итоговые очки и места, рассылка итогов.
6. **Закрыт** (через 24 часа): окончательные очки, обновление цен. Трансферы на следующий тур открыты уже с момента дедлайна (шаг 2).

## 8. Вход и безопасность

- **Вход:** проверка подписи `initData` (HMAC-SHA256 по ключу бота) и срока давности; дальше обычная сессия Supabase. Паролей нет.
- **Сервер решает всё:** дедлайн по серверному времени, бюджет, лимиты, штрафы. Трансфер выполняется в транзакции: целиком или никак.
- **Доступ к данным (Row Level Security):** публичные данные (клубы, игроки, матчи) читают все. Свой состав видишь только ты. Чужие составы открываются после дедлайна. Писать в таблицы напрямую нельзя, только через функции.
- **Админ:** роль `admin` в базе, все админ-действия пишутся в `audit_log`.
- **Защита от спама:** ограничение числа запросов к функциям на пользователя.
- **Секреты** (токен бота и другие ключи) хранятся только в секретах Supabase.
- **Бэкап** базы раз в неделю (на бесплатном тарифе автоматических бэкапов почти нет).

## 9. Надёжность и ошибки

- **Пересчёт с нуля:** очки всегда считаются заново из статистики, поэтому повторный запуск безопасен и не даёт «двойных» очков.
- **Ручная правка важнее источника:** запись с `manual_override` загрузчик не перезаписывает.
- **Источник недоступен или изменил разметку:** повтор позже; в приложении надпись «очки обновятся через несколько минут»; данные не теряются.
- **Новый футболист в источнике** (трансферное окно) добавляется автоматически с базовой ценой и помечается «на проверку» в админке.
- **Неизвестный игрок или матч** в данных источника не ломает загрузку: запись откладывается и попадает в журнал.
- **Межсезонье:** бесплатный проект Supabase может «уснуть»; перед сезоном его включают, данные сохраняются.

## 10. Проверка качества

1. **Модуль подсчёта очков** — отдельный, без доступа к базе: «статистика + позиция + правила → очки». На каждое правило из 4.4 есть автотест: гол защитника, «сухой» матч при замене, 2 пропущенных, автозамена, капитан не вышел, двойной тур.
2. **Автотесты трансферов:** бюджет, 3 на клуб, дедлайн, −4, накопление бесплатных трансферов, Wildcard.
3. **Проверка входа:** поддельная или просроченная подпись Telegram отклоняется.
4. Автотесты запускаются при каждом изменении кода (GitHub Actions).
5. **Генеральная репетиция:** прогон сыгранных туров ҚПЛ-2026 через систему с ручной сверкой очков нескольких футболистов.
6. **Закрытая бета:** 10–20 человек играют первые туры 2027 года.

## 11. Юридические вопросы

| Вопрос | Что делаем |
|---|---|
| **Персональные данные** (закон РК «О персональных данных и их защите»: хранение данных граждан РК на территории РК) | Требование действует сразу, не только для бизнеса. На этапе 1 храним минимум (Telegram-ID, отображаемое имя). До массового привлечения игроков консультируемся с юристом и при необходимости переносим базу на казахстанский хостинг (PostgreSQL переносится без переписывания). |
| **Логотипы клубов** (товарные знаки) | В закрытой бете используем. До коммерческого запуска нужно разрешение клубов или ПФЛК. Это хороший повод для партнёрства. |
| **Фото футболистов** | Права у клубов и фотографов. Пока заглушка, фото только с разрешения. |
| **Данные лиги** (kffleague.kz) | На этапе 1 читаем только открытые страницы, соблюдаем `robots.txt` и бережную частоту. До коммерческого запуска нужно официальное разрешение или договор с лигой. |
| **Название «QPL»** похоже на официальное сокращение лиги (ҚПЛ/КПЛ) | В приложении и боте пишем «Неофициальная фэнтези-игра, не связана с ПФЛК». До коммерческого запуска проверяем, не конфликтует ли название с товарными знаками лиги, и регистрируем своё. |
| **Призы и платный вход** | На этапе 1 нет. Денежные призы и платное участие только после консультации юриста: это может подпадать под регулирование азартных игр. |
