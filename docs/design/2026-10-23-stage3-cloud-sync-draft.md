# Этап 3: автоматическая загрузка матчей в облаке — черновик архитектуры

Черновик для обсуждения перед планом этапа 3 (спецификация 5.3, 5.4, 7, 9). Сейчас очки в облаке появляются только после ручного `rehearsal` + `deploy:seed`.

## Что уже готово и переиспользуется

- `packages/kffleague`: разбор страниц матчей и карты сайта, вежливый загрузчик. Импортов `node:` нет, поэтому он собирается в Edge Function тем же `esbuild`, что и функции этапа 2.
- `packages/db/src/sync.ts`: `syncSeason`, `upsertMatch` (не перезаписывает `manual_override`), `rebuildFromRaw`. Работают с любым `postgres.Sql`, значит, и с `npm:postgres` в Deno.
- `packages/core`: подсчёт очков игроков и команд, автозамены, капитан.
- `packages/db/src/squad.ts`: `ensureSquadTx` для переноса состава.

## Новые функции (Edge Functions, вызываются по расписанию)

| Функция | Когда | Что делает |
|---|---|---|
| `sync-fixtures` | каждые 3 часа | карта сайта → новые и перенесённые матчи сезона, пересчёт туров и дедлайнов (`reassignGameweeks`); только Премьер-лига (240 матчей) |
| `sync-live` | каждые 15 минут, только пока идёт матч | страница каждого идущего матча → `upsertMatch` → очки игроков |
| `sync-final` | после финального свистка и повторно через 2 часа | перезагрузка завершённых матчей: лига может поправить протокол |
| `gameweek-finalize` | после последнего матча тура и окончательно через 24 часа | `ensureSquad` для **всех** пользователей тура, затем `scoreGameweekTeam`: автозамены, очки, штрафы → `gameweek_scores` (очки, сумма за сезон, место) |
| `prices-update` | между турами (после окончательного закрытия) | `priceDelta` по чистым покупкам (пороги из настроек сезона), `clampPrice` 3.5–12.0 |

## Расписание

`pg_cron` + `pg_net` в Supabase: задача по расписанию делает HTTP-вызов функции с секретным заголовком (`CRON_SECRET` в секретах Supabase). Функция проверяет заголовок; без него — 401. Окна `sync-live` считаются по `fixtures.kickoff`: вне игровых окон функция ничего не скачивает.

## Надёжность (спецификация 9)

- Все запросы к сайту пишутся в `source_usage`, есть дневной лимит (как в этапе 1).
- Сайт недоступен или разметка изменилась — матч откладывается, ошибка уходит в журнал. В приложении в идущем туре уже есть надпись «очки обновляются каждые несколько минут».
- Пересчёт всегда идёт с нуля из статистики, повторный запуск безопасен.
- Неизвестный игрок добавляется с базовой ценой и пометкой `needs_review`.

## Решения владельца (23 октября 2026)

1. **Обновление идущих матчей — раз в 15 минут** (не 2–3 минуты). Одна задача по расписанию `cron-tick` каждые 15 минут делает всё: календарь (не чаще раза в 3 часа), идущие матчи, повторную загрузку через 2 часа после финала, итоги тура, цены, уведомления.
2. **Спорные цифры правит Claude** по запросу владельца (скрипт с `manual_override` и записью в `audit_log`). Админки в этапе 3 нет.
3. **Уведомления в боте нужны:** за 24 часа и за 2 часа до дедлайна, итоги тура. Отключаются переключателем в профиле.
4. **Письмо в ПФЛК пока не отправляем.**

Мини-лиги и команда `/start` в боте (спецификация 5.2, 5.5) — следующий план, не этот.
